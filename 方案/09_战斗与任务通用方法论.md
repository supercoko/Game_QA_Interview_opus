## 二、战斗

### 2.1 通用模型：六层拆解

不管是实时动作、回合制还是自走棋，战斗都可以拆成六层。测一个新角色或新机制时，逐层问一遍：

| 层 | 测什么 | 判定依据 | 上线案例 |
| --- | --- | --- | --- |
| **1 数值** | 公式、乘区、取整、上下限、阈值分段 | 独立的公式计算器 | 绝区零 1.4：异常精通**已达到 600** 后继续提升，增益低于预期 |
| **2 规则** | 触发条件、作用对象、叠加与覆盖、优先级、属性的作用范围 | 规则拆解卡 + 交互矩阵 | 原神 1.3：芭芭拉命座 6、七七命座 6、凯亚命座 4 等效果**错误地受到冷却缩减影响** |
| **3 状态** | 前台/后台、死亡/复活、被控制、形态、失衡、进出副本 | 状态迁移图 | 绝区零 2.6：般岳让敌人失衡时间延长，敌人**退出失衡后再次进入**，效果不再生效 |
| **4 时序** | 事件顺序、窗口期、打断、暂停 | 时间轴插入 | 绝区零 2.6：耀嘉音触发快速支援并**换人**后，新上场的代理人短时间内无法格挡、无法正常受击 |
| **5 表现** | 特效、动作、镜头、伤害数字、描述文本 | 描述 = 配置 = 实际结算 | 原神 2.1：旅行者（雷）命座 6 的描述与实际效果不一致 |
| **6 环境** | 联机、平台、输入方式、网络、特殊玩法对规则的改写 | 矩阵 | 原神 2.6：联机时两个七七，治疗量按**另一位玩家**的攻击力计算 |

### 2.2 四种战斗形态的差异

| | 原神（实时 ARPG） | 崩铁（回合制） | 绝区零（动作） | 因缘精灵（按自走棋类假设） |
| --- | --- | --- | --- | --- |
| 核心机制 | 元素附着与反应、切人、后台效果、大世界地形 | 行动值与速度、行动提前、追加攻击、终结技插入、多波次 | 闪避/招架判定窗口、连携技、快速支援与换人、失衡 | 备战阶段（经济、商店、站位、合成）+ 自动战斗 |
| 时序特点 | 实时，受物理影响 | 离散回合，事件有先后 | 帧级窗口 | 回合大循环，战斗内部按时间步推进 |
| 结果确定性 | 中（实时、物理） | **高**（除去概率触发） | 中低（依赖输入时机） | 取决于随机种子，**测试中必须可控** |
| 数据特征 | 偶现多、位置/地形多、联机多实例 | 描述一致性最高 | 组合最高 | 货币战争：描述一致性和组合最多 |
| 测试重点 | 附着与反应规则、后台效果、联机多实例、地形边界 | 行动序列、插队、波次切换、后台角色、召唤物 | 判定窗口边界帧、换人时序、敌我招式交叠 | 羁绊计数、星级、上限、经济边界、随机分布 |
| 自动化切入点 | 固定场景 + 技能序列 + 事件日志 | 回合日志基线比对、不渲染的战斗模拟 | 帧级输入注入 + 判定日志 | 不渲染的对局模拟 + 大样本统计 |

### 2.3 案例：每种形态挑 4–5 个

**原神（实时 ARPG）**

| 原始记录 | 风险类型 | 怎么测 |
| --- | --- | --- |
| 1.3：目标身上**残留有元素附着**，却无法触发元素反应（例如结晶后附着未耗尽，应能继续触发其他反应） | 规则 + 状态 | 把附着当成「有余量的资源」，测：触发一次反应后余量是否正确、余量未耗尽时还能不能触发下一次 |
| 1.3：多个命座效果**错误地受到冷却缩减影响** | 规则：属性的作用范围 | 新属性上线时，列出「它应该作用于哪些效果、不应该作用于哪些」，逐个验证 |
| 3.2：赛诺在「末途真眼」状态下放战技**被打断**，下一次即使不在该状态，仍会触发「裁定」 | 状态残留 | 每个带状态的技能，都测「被打断」这条退出路径 |
| 2.6：联机时**两个七七**，治疗量有概率按另一位玩家七七的攻击力计算 | 环境：多实例 | 联机双方用同一角色，并把属性差距拉大，否则取错了人也看不出来 |
| 1.4：单人模式下打开菜单**暂停游戏**，可导致元素反应触发异常 | 时序：暂停 | 「暂停」是每个新机制都要检查的固定项 |

**崩铁（回合制）**

| 原始记录 | 风险类型 | 怎么测 |
| --- | --- | --- |
| 2.1：**多个角色装备**「游戏尘寰」时，任意一个装备者的【假面】结束，会连带解除其他装备者的增益 | 多实例 | 同一效果有两个来源时，分别结束，检查是否互不影响 |
| 1.3：**相邻波次**敌方等级不同时，第二波敌方出现时等级错误 | 状态：波次切换 | 多波次战斗里，波次之间哪些状态该重置、哪些该继承，列表逐项检查 |
| 4.7：忆灵施放技能后，「使自身所有持续效果持续回合数减 1」的天赋效果异常 | 规则：回合计数 | 回合制里「回合数」是核心资源，召唤物、忆灵的回合计数要单独测 |
| 1.3：与「不死神实·幻胧」战斗中施放「云吟怒啸」后，丹恒异常触发天赋 | 组合：特殊敌人机制 × 角色天赋 | 特殊敌人机制会给角色「借用」技能，要测这些技能会不会触发角色自己的天赋和装备效果 |
| 2.7：光锥「等价交换」效果异常，修复后与 **2.6 版本更新前**一致 | 回归 | 回合制结果确定性高，最适合做「固定队伍 + 固定操作 → 回合日志」的基线比对 |

**绝区零（动作）**

| 原始记录 | 风险类型 | 怎么测 |
| --- | --- | --- |
| 2.8：莱卡恩在敌人发动「控制技」的**同时**发动支援突击，受击异常 | 时序：敌我招式交叠 | 敌人每种特殊招式，都和我方的支援、闪避、终结技做时间上的交叠测试 |
| 2.6：耀嘉音触发快速支援并**换人**，把后台正在追加攻击的代理人换回前场后，短时间内无法格挡、无法受击 | 时序 + 状态：换人 | 换人是动作游戏的核心状态切换：换下时正在做什么、换上时状态是否完整 |
| 1.4：莱特**闪避后**未点普攻，闪避结束后再点普攻，会跳过第一段直接发动第二段 | 输入缓冲 | 测「输入缓冲窗口」的边界：窗口内、刚好结束、结束后，三种时机的输入分别会怎样 |
| 2.6：般岳让敌人失衡时间延长后，敌人**退出失衡再次进入**时效果未生效 | 状态重入 | 每个「对某状态生效」的效果，都测第二次进入这个状态 |
| 3.3：敌人发动「控制技」时，代理人招式无法正常命中 | 判定 | 敌人处于特殊状态时，我方的命中判定是否仍正确 |

**自走棋类（用崩铁「货币战争」类比）**

| 原始记录（崩铁） | 风险类型 | 对应到自走棋的检查项 |
| --- | --- | --- |
| 4.6：已上阵角色**超出团队规模上限**时，无法把角色下场 | 边界 + 状态 | 上阵上限会因为等级、羁绊、道具变化，测「上限降低后已经超员」这种状态能不能操作 |
| 4.5：银狼 LV.999 与黑天鹅**达到 3 星并同时登场**时，游戏进程异常 | 组合 + 星级 | 高星级单位的特殊效果两两组合，作为高风险用例 |
| 4.3：**改变角色星级的投资策略**，对阵营羁绊「巡海游侠」提供的星级加成生效异常 | 规则叠加顺序 | 多个来源修改同一个属性（星级）时，叠加顺序和上限 |
| 4.3：不死途**位于后台**时，「巡海游侠」羁绊增益计入星级异常 | 羁绊计数范围 | 哪些位置的单位计入羁绊：场上、后台、备战席、召唤物？ |
| 4.5：同时选择投资策略【孪生姵姵】和【艾丝妲的猛犬】时，【穿刺死棘之枪】效果异常 | 三因子组合 | 两两组合（Pairwise）之外，对历史问题多的规则补三因子组合 |
| 4.5：姬子用独立羁绊「领航员」**复制装备**后，无法再通过「魔术师」等途径获得装备 | 装备系统状态 | 复制、转移、合成时装备的归属和数量 |
| 3.8：投资环境【经济过热】【经济严重过热】效果异常 | 经济系统 | 经济规则的分档边界 |
| 3.8：调整了**部分平板设备**的角色出售区域范围 | 输入 × 设备 | 拖拽出售、拖拽上阵的判定区域在不同屏幕尺寸上是否合理 |
| 4.3：备战阶段的场上角色计数显示异常 | 表现一致性 | 计数和上限的显示与实际状态一致 |

### 2.4 通用测试方法：七步

**第 1 步：规则拆解卡**（每个技能、羁绊、装备一张）

| 字段 | 填写示例（假设的技能，仅示意格式） |
| --- | --- |
| 触发条件 | 普攻命中时 / 每回合开始 / 场上同阵营单位 ≥ 3 |
| 作用对象 | 自身 / 全队 / 前台 / 所有单位（含召唤物？） |
| 效果 | 攻击力 +X%，持续 N 秒或 N 回合 |
| 叠加规则 | 同源覆盖 / 不同源叠加 / 上限 M 层 |
| 结束条件 | 到时、被驱散、离场、死亡、战斗结束 |
| 读写的资源 | 能量、行动值、生命、护盾、经济…… |
| 不在场时 | 后台、备战席、死亡时是否生效 |
| 特殊玩法里 | 会被哪些玩法改写？ |

这张卡就是需求评审时的提问清单：哪一格写不出来，就是需求没说清楚。

**第 2 步：数值的独立计算器**

用 Python 或者 Excel 实现一份「按策划文档计算期望值」的计算器，和游戏里的实际结算对比。重点放在阈值和分段点前后（比如 599 / 600 / 601），以及取整方式。

**第 3 步：交互矩阵 + 多实例**

列出「新规则 × 存量规则」，标出读写同一资源的格子；Pairwise 覆盖两两组合；固定加一组多实例检查（同一效果两个来源）。

**第 4 步：状态迁移**

| 形态 | 必测的状态边 |
| --- | --- |
| 实时 ARPG | 前台 ↔ 后台、死亡 → 复活、进出副本、进出特殊玩法、被打断 |
| 回合制 | 波次切换、行动提前/插队、召唤物出现与消失、战斗结束 |
| 动作 | 换人、失衡进入/退出/再次进入、闪避/招架成功后 |
| 自走棋 | 备战 → 战斗 → 结算、上阵 ↔ 下场 ↔ 备战席、星级提升（合成）、出售 |

**第 5 步：时序插入**

在状态的「开始前 / 开始瞬间 / 持续中 / 结束前一刻 / 结束瞬间 / 结束后」插入其他操作；暂停每次都测。自走棋要额外测「备战阶段倒计时归零的瞬间」正在拖拽、正在购买时会怎样。

**第 6 步：三方一致性**

描述、配置、实际结算三者一致。崩铁和货币战争里这一类问题占比最高。

**第 7 步：环境**

联机（多实例、谁的属性是权威）、平台（低画质下的特效，比如原神 3.4 胡桃元素爆发特效在不同平台和画质档位下表现不同）、输入方式（手柄、触屏拖拽区域）、特殊玩法对规则的改写。

### 2.5 自走棋 / 因缘精灵专项清单

> 以下是自走棋类玩法的通用机制，因缘精灵是否有这些机制、具体规则是什么，以实际游戏为准。

| 领域 | 测试点 |
| --- | --- |
| 商店与随机 | 刷新概率是否符合配置（大样本加卡方检验）；如果有公共卡池，被买走后概率是否变化；固定随机种子能否复现 |
| 经济 | 收入、利息、连胜连败奖励的分档边界；金币为 0 和达到上限；出售返还（尤其是已经合成升星的单位） |
| 星级与合成 | 凑齐几个合成升星；场上和备战席的单位能否跨区域合成；备战席满时购买第三个能否触发合成；合成时装备怎么转移 |
| 羁绊 | 阈值档位（比如 2/4/6）；同名单位是否重复计数；后台、备战席、召唤物是否计入（对应货币战争 4.3 案例）；羁绊加成和其他修改来源的叠加顺序 |
| 站位与上限 | 格子边界；拖拽的判定区域（对应货币战争 3.8 平板出售区域）；上阵上限变化后已经超员的处理（对应 4.6 案例） |
| 自动战斗 | 确定性（同输入同结果）；超时判定；双方同时阵亡算谁赢；召唤物；多波次 |
| 回合流程 | 备战 → 战斗 → 结算的每个阶段，断线重连、切后台、中途退出 |
| 对手与匹配 | 如果有异步对手（用其他玩家的阵容快照），阵容数据跨版本兼容吗？对手阵容里有已经被改动的单位怎么办？ |

**能体现深度的两点**

1. **随机性要用统计方法验证**。比如商店刷新概率，用 GM 或服务端模拟跑上万次，用卡方检验比较实际分布和配置的期望分布，不能凭「感觉出得太少」提单。
2. **平衡性是策划的事，异常是测试的事**。不渲染的模拟跑几万场对局，QA 关注的是异常：战斗不结束、数值溢出或出现非法值、崩溃、胜率极端偏离（比如某阵容胜率接近 100%）。发现了就报给策划判断，不替策划下「不平衡」的结论。

## 三、任务

### 3.1 通用模型

```
任务 = 任务状态机（未解锁 → 可接 → 步骤1 … 步骤N → 完成 / 失败）
     × 世界状态（NPC 是否在、物件状态、区域是否开放、天气和时间）
     × 玩家状态（位置、当前角色、衣装、队伍、背包、设置项）
     × 外部事件（断线、重登、死亡、传送、联机、跳过、版本更新）
```

任务 bug 大多不是「状态机画错了」，而是**世界状态或玩家状态和状态机的假设对不上**。

### 3.2 十二类风险与上线案例

| # | 风险类型 | 上线案例 | 测法 |
| --- | --- | --- | --- |
| 1 | **接任务前，世界状态已被改变** | 原神 7.1：**接取**世界任务「时常于水波之下」**前**清除了任务区域附近的碎冰，导致任务无法继续 | 每个任务依赖的世界物件，都测「玩家提前改动过」的情况 |
| 2 | **步骤顺序被打破** | 原神 5.1：「黑岩之困」在「外围巡查」阶段**就提前击败**相关敌人，后续目标无法进行 | 大世界里玩家会先做后面的事：每一步都测「提前完成下一步的条件」 |
| 3 | **任务之间冲突** | 原神 月之八：开启魔神任务「道成千壑，因果异灭」时，卡维邀约事件「旧物」和艾尔海森传说任务「傲慢偏见」的目标无法完成 | 新任务上线时，列出共用 NPC 和区域的存量任务，做冲突矩阵 |
| 4 | **玩家外观、角色变化** | 原神 月之五：旅行者**换衣装**后，部分任务对话里出现两位旅行者，或任务玩法无法完成；终末地 09-02：编入试用编队的自有干员，会异常变回试用干员 | 任务里的演出和逻辑不要假设玩家的外观、角色是默认的 |
| 5 | **设置项影响** | 原神 3.1：「缄默的求知者」因为**镜头默认距离被修改**导致任务无法完成 | 依赖视角、画面的任务玩法，测非默认的镜头和画质设置 |
| 6 | **离开预期路径或区域** | 原神 3.0：离开任务目标范围后无法退出潜行模式；原神 5.1：收集时离开任务区域，角色有概率卡死；原神 月之一：错过通行模块或从上面坠落，任务无法继续 | 每个限定区域、限定载具的步骤，都测离开、坠落、错过 |
| 7 | **跳过和非常规路径** | 崩铁 4.1：**跳过**部分段落对话后，游戏进程异常 | 跳过、回顾、重播的路径要和正常播放一样经过完整的状态更新 |
| 8 | **中途退出、断线、重登** | 崩铁 2.5：与飞霄谈判**中途退出**，重新登录后直接判定失败；原神 2.3：接取「门户清理」后，**登录游戏**时异常黑屏 | 每一步 × 断线、重登、杀进程，见 [02 案例 6](02_测试方法论与真实案例.md) |
| 9 | **NPC、物件异常** | 原神 7.1：「跟随小狗」时小狗有概率不移动；崩铁 1.4：「诗仙机器人」流程中同时出现两个 NPC「明阅」；崩铁 2.1：与砂金对话时所处的场景错误，导致对话结束后场景内的普通战利品消失 | 每一步前后，对相关 NPC 和物件做状态快照比对 |
| 10 | **任务道具与已受影响的数据** | 原神 2.8：完成「扇底春秋」时，「匪石」的任务道具「老石」异常消失，修复后自动补发；崩铁 3.5：无法推进「蝮蛇鸩鸟，万寿迢迢」，修复后玩家可重新追踪任务继续 | 修复时除了改代码，还要处理已经卡住的玩家：补发、重新追踪，并验证补救方案 |
| 11 | **战斗技能 × 任务** | 崩铁 4.1：部分任务流程中，流萤施放秘技后模型消失、无法移动；终末地 10-15：支线「终其一生」中部分敌人消失，无法推进 | 任务里的战斗和移动环节，用会改变状态的角色技能（变身、位移、隐身）测一遍 |
| 12 | **入口的地点假设** | 原神 月之二：在蒙德**以外**的凯瑟琳处领取每日委托奖励后，回到蒙德，无法完成相关世界任务 | 同一个功能有多个入口时，每个入口都走一遍完整流程 |

### 3.3 不同项目任务的侧重

| 项目 | 侧重 |
| --- | --- |
| 原神 | 大世界非线性：玩家可以提前做、乱序做（风险 1、2、6）；联机（原神 2.2「清籁逐雷记」进入多人模式有概率导致任务无法完成）；每日委托等周期性任务（任务模块中时间周期类占 9.4%） |
| 崩铁 | 线性叙事 + 战斗嵌入 + 秘技：跳过对话、秘技、对话选项分支（风险 7、8、11） |
| 绝区零 | 公告里任务分类的数据太少，按通用方法准备；面试前实际玩一下，说出你观察到的任务结构 |
| 终末地 | 试用编队、任务追踪跳转（09-02：追踪需要打开【BAKER】的任务时，无法跳转到对应界面）、拍照功能拖动角色后关卡无法继续 |
| 因缘精灵 | 没有数据，按通用模型准备；如果任务和自走棋对局结合（比如「用指定阵容通关」），要测任务条件和对局结果的判定 |

### 3.4 任务测试方法

1. **任务结构表**：每一步写清楚开启条件、完成条件、世界状态变化（NPC、物件、区域、天气）、给予和收回的物品、失败条件、存档点。这张表就是用例的骨架。
2. **乱序、提前、重复**：「玩家不按顺序玩」是大世界任务最大的风险来源。
3. **中断矩阵**：每一步 × 断线、重登、死亡、传送、离开区域、切换角色、进入联机。
4. **冲突矩阵**：共用 NPC、区域、时间段的其他任务和活动。
5. **玩家状态变量**：角色、衣装、队伍、设置项、载具或形态。
6. **存量玩家**：版本更新时，停在每一步的账号是否还能继续（准备账号快照）。
7. **静态检查**：任务图里引用是否存在、有没有死路、有没有到不了的节点。你做过 FlowGraph 静态检查，这一项可以讲出真实经历。
8. **自动化巡检**：GM 跳到指定步骤 + 传送或寻路 + 自动推进对话，每一步后断言任务状态和世界状态快照；目标是「每一步都能推进」，不是替代人工体验剧情。

### 3.5 任务卡死的排查流程

1. **确认卡在哪一步**：用任务日志或 GM 查询当前步骤和条件变量的值；
2. **哪个完成条件没满足**：事件没发出？没被监听？条件被提前消耗了（风险 2）？
3. **世界状态对不对**：需要的 NPC、物件在不在、状态对不对（风险 1、9）；
4. **客户端和服务端是否一致**：重新登录能不能恢复？
5. **给出规避方案**：比如重新追踪、重新登录，同步给客服；
6. **修复后的存量玩家**：已经卡住的玩家怎么处理，补救方案也要测（风险 10）。

## 四、面试问答

> 格式：**怎么问** → **回答要点** → **可能的追问** → **结合你的经历**。

### 战斗

**Q1：给你一个新角色（新技能），你怎么测？**

- **回答要点**：按六层拆，每层一句话。数值用独立计算器；规则用拆解卡和交互矩阵；状态用状态迁移图；时序用时间轴插入；表现和描述做三方一致；环境测联机、平台、特殊玩法。再按数据排优先级：组合和时序最容易出功能错误。
- **追问 1：组合太多怎么办？** → 先用交互矩阵筛出读写同一资源的组合，再用 Pairwise 覆盖两两交互，对历史问题多的规则补三因子组合（比如货币战争 4.5 的两个投资策略 × 一件装备）。
- **追问 2：测试数据怎么选？** → 要能区分对错：联机双方同一角色时属性差距要拉大，阈值前后都要取点。
- **结合经历**：基础战斗冒烟验证的是链路；死亡 + 升级的问题，就是状态层和时序层交叉的例子。

**Q2：回合制和动作游戏的战斗测试，有什么不一样？**

- **回答要点**：回合制的结果确定性高，最适合「公式计算器 + 回合日志基线比对」，重点是行动序列、插队、波次切换、后台和召唤物，崩铁描述一致性类问题占比最高，说明三方一致性是重点。动作游戏的重点是帧级窗口：闪避和招架的判定、输入缓冲、换人时序。绝区零的组合类问题占比是四款里最高的，敌我招式交叠、换人都是高发区。
- **追问：动作游戏的判定窗口怎么测？** → 先拿到窗口的设计值（第几帧到第几帧），用慢动作或时间缩放放大窗口，在边界帧前后输入；自动化可以在指定帧注入输入，统计成功率。绝区零 1.4 莱特「闪避后跳过普攻第一段」就是输入缓冲窗口的边界问题。

**Q3：伤害公式怎么验证？**

- **回答要点**：独立实现一份计算器，按策划文档的乘区计算期望值；逐个乘区隔离验证（只改一个变量，其他固定）；重点测阈值、分段点、取整、上下限；读战斗日志的原始数值，不读 UI 上的数字。
- **追问：有暴击和浮动怎么办？** → 测试环境固定随机种子，或者用 GM 关闭随机；概率本身另外用大样本统计验证。

**Q4：Buff 的叠加和覆盖怎么测？**

- **回答要点**：同源和不同源；层数上限；刷新持续时间还是独立计时；有多个实例时一个结束会不会影响另一个（崩铁 2.1「游戏尘寰」）；驱散；离场和死亡时的处理。
- **追问：怎么知道叠加规则对不对？** → 先要求策划在规则拆解卡里写清楚；写不清楚的，本身就是需求风险。

**Q5：（原神）元素反应怎么测？**

- **回答要点**：把元素附着当成「有余量、会衰减的资源」：附着、消耗、残留、反应的优先级。原神 1.3 有一条修复：目标身上残留附着时无法触发反应，就是余量模型的边界问题。再加上多实例（联机两个同元素角色）、暂停（原神 1.4 暂停导致元素反应异常）、后台角色的附着。

**Q6：（因缘精灵）自走棋玩法的随机性和平衡你怎么测？**

- **回答要点**：随机性用统计方法：大样本 + 卡方检验，固定种子保证可复现；平衡性是策划决策，QA 用不渲染的大量模拟找异常（战斗不结束、非法数值、胜率极端），把数据交给策划判断。再讲羁绊计数范围、星级来源的叠加顺序、上阵上限变化这几个具体检查项，用货币战争的案例佐证。
- **追问：你玩过因缘精灵吗？** → [必须真实回答]。玩过的话，说出 1–2 个你观察到的具体机制，以及你会怎么测；没玩过就不要假装。

**Q7：战斗自动化怎么做？**

- **回答要点**：分三层。冒烟（链路通，你做过）→ 数值基线（固定种子 + 事件日志 + 版本间差异比对）→ 组合回归（配置驱动 + Pairwise）。回合制和自走棋适合不渲染的模拟，跑得快；动作游戏需要帧级的输入注入。见 [04 方案四](04_自动化与工具方案_UE主线.md)。
- **结合经历**：从你的 Functional Test 冒烟讲起，再讲你会怎么升级。

**Q8：打击感、手感这类问题，你怎么提？**

- **回答要点**：客观问题（判定不准、动作卡住、穿模）附录像和帧数据作为 bug 提；主观体验（硬直太长、反馈不明显）作为体验建议提给策划，附对比，不和 bug 混在一起。相机部分可以引用你做过的相机测试经验。

### 任务

**Q9：一个新的主线任务，你怎么测？**

- **回答要点**：先建任务结构表（每一步的开启、完成、世界状态、物品）；然后按十二类风险过一遍，最重要的几类是乱序和提前、中断矩阵、任务冲突、玩家状态变量；最后是存量玩家和补救方案。强调数据：任务问题漏到线上时阻断占 19.4%，所以第一目标是「怎么玩都不会断」。
- **追问：时间不够，先测什么？** → 先测会卡死流程的（乱序、离开区域、断线重登、冲突），再测表现。

**Q10：玩家反馈任务卡住了，你怎么排查？**

- **回答要点**：按 3.5 节的六步讲：哪一步 → 哪个条件 → 世界状态 → 客户端和服务端是否一致 → 规避方案 → 存量玩家处理。
- **结合经历**：你在背包测试里「关注任务进度与场景切换下的数据一致性」，以及死亡 + 升级问题的日志定位，都是同样的排查思路。

**Q11：版本更新改了任务，老玩家正好卡在中途怎么办？**

- **回答要点**：准备「停在每一步」的账号快照，更新后逐个验证还能不能继续；不能继续的，要有数据修复或重新追踪的方案（崩铁 3.5 的做法是修复后玩家可重新追踪任务继续）；补救方案本身也要测：不重复发奖、不漏发。

**Q12：任务能自动化吗？怎么做？**

- **回答要点**：能做「流程巡检」：GM 跳步 + 传送或寻路 + 自动推进对话，每一步断言任务状态和世界状态；适合发现「推不动」的问题，不适合验证剧情体验。再加静态检查（引用存在、无死路）。
- **结合经历**：采集物自动化里你已经用过 GM 传送 + Poco 交互 + 证据留存，可以直接迁移到任务巡检；FlowGraph 静态检查对应任务图的结构检查。

**Q13：任务的静态检查能查什么？查不了什么？**

- **回答要点**：能查结构：引用的 ID 是否存在、必填参数、死路、不可达节点、无退出的环。查不了运行时：原神 5.1「黑岩之困」提前击败敌人、原神 7.1 接任务前清了碎冰，这两张图的结构都合法。所以静态检查和动态测试要分工。
- **结合经历**：FlowGraph 静态检查，[填写你写过的规则]。

**Q14：（原神）多人模式下的任务怎么测？**

- **回答要点**：哪些任务允许联机、哪些会被限制；联机进入和退出时任务状态怎么处理（原神 2.2「清籁逐雷记」进入多人模式有概率导致任务无法完成）；主机和客机看到的 NPC、物件是否一致；任务物品归属。
